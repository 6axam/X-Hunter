# Архитектура

`gateway` собирает React/Vite Mini App, раздаёт его через Caddy и проксирует `/api`. FastAPI отвечает за Telegram-сессию, ownership, черновики, поиски, ленту, настройки, медиа и экспорт. aiogram принимает три команды и OLX-ссылки. Celery worker выполняет сканирование, медиа, ИИ и outbox; один beat scheduler назначает due-задачи. PostgreSQL хранит данные, Redis — очередь.

Источник отделён интерфейсом `ListingSource`. URL и HTML разбираются чистыми функциями с фикстурами. При сетевом запуске выдача сначала даёт кандидатов, затем загружается полная карточка; после этого применяются description-правила. Баннеры исключаются, promoted/organic копии одного ID объединяются.

Первый проход создаёт baseline без потока старых уведомлений. Новые ID формируют уникальный outbox event на владельца и объявление. Несколько поисков получают свои `search_matches`, но первичное сообщение одно. Версии значимых данных позволяют обнаруживать падение цены. После двух независимых подтверждённых `404/410` удаляется корневой `listing`; cascade удаляет версии, связи, saved/note, AI, media и историю событий.

OpenRouter получает недоверенный текст отдельным user message, без tools и секретов. Ответ ограничен JSON Schema и валидируется Pydantic; цитаты должны присутствовать в исходном тексте. До запроса резервируется известная максимальная стоимость. Неизвестная доставка Telegram и неизвестная стоимость ИИ сохраняются отдельными состояниями.

## X-Hunter Agent v2

Исследование покупки выполняется как ограниченный устойчивый цикл: `Understand → Plan → Search → Filter → Evaluate → Reflect → Replan → Compare → Finalize`. Перед построением URL Luna формирует публичную техническую сводку задачи, ограничения, неизвестные и гипотезы модельных семейств. Планировщик превращает это в короткие поисковые фразы OLX; назначение товара и бюджет не подмешиваются в фразу.

Каждая сессия сохраняет техническую сводку, гипотезы, раунды, фактически выполненные URL, решения Supervisor, сводную память, рыночную статистику, финальное сравнение и usage по этапам. Активный раунд сохраняет кандидатов до завершения, поэтому перезапуск не повторяет уже выполненные фразы или завершённые оценки. После каждого раунда Supervisor получает компактные проверяемые факты и выбирает продолжение, уточнение стратегии, альтернативное направление, завершение либо важный вопрос пользователю. Его решение реально создаёт следующий раунд; число раундов и фраз на раунд ограничено настройками.

Диагностическая трасса хранится отдельными JSON-событиями в PostgreSQL и участвует в тех же checkpoint-транзакциях, что и исследование. Она связывает техническую сводку, стратегии, OLX-запросы, prefilter, модельные ответы, Supervisor, статистику и финальный выбор через `research_id`, `round_id`, `query_id` и `listing_id`. Автопроверки добавляют события противоречий, не меняя решений агента. Запись ограничена по числу событий, размеру события и общему объёму; старые события удаляются Celery beat.

Owner-scoped ZIP-экспорт содержит `trace.jsonl`, `summary.json`, `manifest.json` и `report.md`. Перед записью и повторно при экспорте маскируются секреты, HTTP-заголовки, контакты и профиль продавца. Скрытое внутреннее рассуждение модели не записывается: в трассу попадают только структурированные входы, ответы и обоснования.

Локальный фильтр сначала определяет основной объект по заголовку и подробной карточке. Упоминание зарядки или батареи в комплекте не превращает ноутбук в аксессуар; отдельный блок питания отсекается. Подтверждённая запрещённая платформа (например, AMD при жёстком запрете) отклоняется, а неизвестный CPU остаётся кандидатом с риском. Рыночные диапазоны строятся только по уникальным оценённым карточкам с актуальными сохранёнными ценами; при малой или разнородной выборке это явно отмечается.

Файлы медиа доступны через owner-protected API. Downloader разрешает HTTPS-хосты из allowlist, проверяет DNS/IP, redirects, MIME, сигнатуру, размер и pixel count; путь строится по checksum.
