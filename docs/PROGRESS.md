# Прогресс OLX Hunter

Обновлено: 2026-10-10.

## Реализовано

- Создан Git-репозиторий и базовая структура проекта.
- Добавлены безопасный шаблон окружения и правила исключения секретов/рабочих данных из Git.
- Создан backend-каркас FastAPI с request ID и единым прикладным форматом ошибок.
- Добавлен заменяемый интерфейс `ListingSource` и начальный адаптер OLX.
- Реализован чистый импорт и обратная сборка URL OLX: цена, валюта, продавец, сортировка, непрозрачные параметры, удаление tracking/page.
- Ссылки других доменов, нестандартные порты, credentials и некорректные диапазоны цены отклоняются.
- Сетевой источник честно возвращает `not_configured`; живой сбор пока выключен.
- Зависимости backend зафиксированы в `backend/uv.lock`.
- Добавлены SQLAlchemy-модели всех основных сущностей раздела 22 и первая Alembic-миграция.
- Реализована явная dev-аутентификация с привязкой к `OWNER_TELEGRAM_ID`; произвольный первый посетитель владельцем не становится.
- Реализованы API импорта ссылки, редактирования черновика и CRUD поиска с проверкой владельца и optimistic revision.
- Ссылка отдельного объявления распознаётся, но не может быть ошибочно запущена как мониторинг выдачи.
- Добавлены HTML-парсеры выдачи и полной карточки на контролируемых фикстурах: рекламные блоки пропускаются, продвинутая и органическая копии дедуплицируются.
- Добавлена детерминированная фильтрация цены, групп обязательных слов, отрицательных слов со случаем простого отрицания и accessory-only режима.
- Реализованы версии объявлений, связи с несколькими поисками, baseline без массовой рассылки и outbox-события `new_listing`/`price_drop`.
- Реализовано каскадное удаление объявления, его истории, saved-состояния и связей только после двух подтверждённых проверок недоступности; блокировка/сетевой сбой удалением не считаются.
- Реализована проверка Telegram Mini App `initData` по официальному HMAC-алгоритму, ограничение возраста, owner allowlist, подписанная HttpOnly-сессия и CSRF-защита изменяющих запросов.
- Уточнено поведение строгих отрицательных слов: они не выполняют смысловой анализ отрицания; такой анализ будет доступен только через ИИ.
- Добавлены API ленты и полной карточки находки, фильтр сохранённых и изменение saved/hidden/seen/note с проверкой владельца.
- Добавлен ручной запуск проверки с возвратом существующего active run и честным состоянием `not_configured`, пока HTTP-источник выключен.
- Решения фильтра приведены к контракту `match|reject|uncertain`.
- Собран React/Vite Mini App с адаптивной мобильной нижней навигацией и desktop sidebar; основные разделы — «Поиски», «Находки», «Настройки».
- Реализованы импорт и редактор черновика, создание/пауза/ручная проверка поиска, общая лента, фильтр сохранённых, optimistic bookmark и полная карточка с переходом в OLX.
- Добавлены загрузочные, пустые, ошибочные и отключённые состояния; интерфейс использует Telegram theme/safe-area и внешний link adapter.
- Сервер пересобирает URL после изменения распознанной цены; клиент не конструирует OLX URL самостоятельно.
- Frontend-зависимости зафиксированы в `package-lock.json`; после обновления Vitest `npm audit` не находит уязвимостей.
- Добавлен aiogram-бот с owner allowlist, командами `/start`, `/app`, `/help` и импортом OLX-ссылки через общий `SearchService`.
- Добавлена доставка outbox с двумя кнопками, журналом попыток, обработкой `429`, блокировки бота и состоянием `delivery_unknown` без опасного автоматического повтора.
- Добавлены Celery worker/beat задачи для планирования due-поисков, запуска scan и доставки pending-уведомлений.
- Добавлен безопасный media pipeline: HTTPS/CDN allowlist, DNS/IP-проверка против SSRF, ручная проверка redirect, лимиты bytes/pixels, Pillow decode и генерируемые checksum-пути.
- Изображения загружаются только для подходящих объявлений, выдаются через owner-protected API и обрабатываются отдельной Celery-задачей.
- Добавлен OpenRouter-клиент по актуальному API: каталог совместимых моделей, strict JSON Schema, `require_parameters`, отключённый fallback и проверка доказательных цитат.
- Реализованы дневной бюджетный резерв до ИИ-вызова, учёт фактической/неопределённой стоимости, кэш оценки и отображение value label/summary в ленте.
- Добавлены versioned owner settings, usage API и CSV/JSON-экспорт на 24 часа; CSV защищён от formula injection.
- Реализован opt-in HTTP-адаптер OLX: ограниченные redirects/body/timeouts, отдельные состояния blocked/partial/removed, разбор выдачи и догрузка полной карточки перед фильтрацией.
- Добавлены Dockerfile backend/gateway, Caddy и Compose-сервисы `gateway/api/bot/worker/scheduler/postgres/redis` с persistent volumes и healthchecks.
- `scripts/setup` генерирует внутренние секреты; добавлены backup, restore и restore-test для чистой PostgreSQL-базы.
- README и документация запуска, архитектуры и эксплуатации приведены в соответствие с фактически собранными компонентами.

## Проверено

- `PROJECT_PLAN.md` прочитан полностью, основной контракт реализации находится в разделе 22.
- В текущем каталоге и доступных каталогах пользователя отсутствует `OLX_HUNTER_UI_PROMPT.md`.
- `ruff check` и форматирование backend проходят.
- `pytest`: 35 тестов проходят, включая URL round trip, сетевой адаптер на контролируемом HTTP, описание, рекламу/дедупликацию, baseline, скидку, очистку, Telegram, outbox, медиа, ИИ и экспорт.
- Первая миграция проверена полным циклом `upgrade head` и `downgrade base` на чистой SQLite-базе.
- Frontend: `npm run typecheck`, 2 Vitest-теста и production build проходят; desktop empty-state визуально проверен во встроенном браузере.
- `docker compose config` проходит и перечисляет все 7 сервисов; `.env` создан setup-скриптом с правами `0600` и не отслеживается Git.

## Открытые проблемы

- Подробная UI-спецификация `OLX_HUNTER_UI_PROMPT.md` не предоставлена. До её появления интерфейс реализуется по разделу 22 плана; окончательная UI-проверка будет нужна после добавления файла.
- Допустимый и стабильный живой источник OLX не подтверждён. Адаптер и парсеры будут проверяться на локальных фикстурах, без ложного заявления о работающем мониторинге.
- Нет внешних реквизитов Telegram, OpenRouter и публичного HTTPS-размещения.
- Docker image build не выполнен: текущий пользователь не имеет доступа к `/var/run/docker.sock`. Конфигурация Compose проверена статически; runtime/restore smoke test требует работающего Docker daemon.
