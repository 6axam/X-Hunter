**План Telegram-бота для мониторинга OLX с Mini App и необязательным ИИ**

Дата исследования: 10 октября 2026 года. Статус: концепция и план будущей реализации; программный код не создавался. Описанные настройки, сроки и показатели качества — проектные предложения, а не результаты испытаний готового бота.

Рабочее предположение: первая версия для одного владельца, OLX.ua, интерфейс на русском с возможностью добавить украинский. Основные категории для начала — товары, прежде всего электроника. Автомобили, недвижимость и другие категории получают свои схемы фильтров по мере проверки. Архитектура допускает нескольких пользователей, но публичный сервис не входит в первую версию.

**1. Пользователь получает личный сервис поиска подходящих объявлений.**

Ты отправляешь боту ссылку на поисковую выдачу OLX. Бот импортирует поддерживаемые параметры, предлагает дополнить условия и создаёт отдельный поиск. В Mini App можно менять цену, местоположение, ключевые слова, требования к описанию, расписание и модель ИИ. Бот проверяет выдачу, сохраняет подходящие объявления с фотографиями и присылает новые совпадения в Telegram.

Единица управления — «Поиск»: например, «Steam Deck до 12 000», «Монитор для работы», «Видеокарта без ремонта». Каждый поиск имеет отдельные настройки, историю и кнопку паузы. Несколько поисков работают независимо, но используют общую базу объявлений и общий контроль нагрузки.

Базовая цепочка: ссылка OLX → параметры поиска → получение карточек → обычные фильтры → полное описание → ИИ при необходимости → сохранение → уведомление → переход в OLX.

**2. Исследование подтвердило реализуемость интерфейса, но выявило ограничения источника данных.**

| Что проверено | Результат | Решение для проекта |
|---|---|---|
| Официальный API OLX | FAQ прямо исключает доступ к чужим объявлениям через партнёрский API | Не строить мониторинг общей выдачи на Partner API |
| Публичная выдача | Видны объявления, цены, состояние, расположение, рекламные блоки и страницы результатов | Отдельный модуль чтения выдачи; устойчивость ещё предстоит испытать |
| Фильтры в браузере | Цена от/до, частные продавцы и сортировка по новизне меняют URL | Реализовать двусторонний перевод между ссылкой и формой |
| Страница объявления | В проверенном примере доступны описание, числовой ID и несколько ссылок на фотографии | Получать подробности отдельно от выдачи |
| Широкий поиск | В проверенной категории отображаются более 1 000 результатов и пагинация до страницы 25 | Показывать фактическое покрытие; не обещать выгрузить весь OLX |
| Telegram | Есть Mini Apps, сообщения с фото, альбомы и кнопки | Mini App для управления, чат для уведомлений |
| OpenRouter | Есть структурированные ответы у совместимых моделей и настройки маршрутизации | ИИ возвращает проверяемое решение в заданном формате |

Основания: [FAQ OLX, вопрос 6](https://developer.olx.ua/ua/articles/faq), [документация Partner API](https://developer.olx.ua/api/doc), [проверенная категория OLX](https://www.olx.ua/uk/elektronika/), [пример карточки объявления](https://www.olx.ua/d/uk/obyavlenie/lot-videokart-p102-100-10gb-12-sht-ID11mD3B.html), [Telegram Mini Apps](https://core.telegram.org/bots/webapps), [структурированные ответы OpenRouter](https://openrouter.ai/docs/guides/features/structured-outputs).

Это проверка страниц и документации, а не нагрузочное испытание. Доступность круглосуточного сбора с будущего сервера, стабильность структуры данных и полный набор параметров всех категорий пока не установлены.

**3. До запуска нужно определить допустимый способ использования данных OLX.**

В прочитанной странице действующих правил пункт 2.3 ограничивает использование контента без письменного согласия правообладателя и запрещает агрегацию и обработку информации для дальнейшей передачи третьим лицам. Пункт 2.4 не предоставляет разрешение на использование соответствующих прав. Это существенная зависимость для хранения фотографий, копирования описаний, рассылки и передачи текста внешнему ИИ. Личное использование само по себе не подтверждает разрешение. [Правила OLX](https://help.olx.ua/olxuahelp/s/article/kA009000001vEvTCAU).

Для запуска следует выяснить условия разрешённого доступа и использования контента у OLX/правообладателей либо выбрать источник с соответствующими правами. Платный посредник не решает вопрос автоматически: отдельно проверяются его права и условия. На странице также объявлено обновление правил с 23 октября 2026 года; при запуске после этой даты потребуется проверить новую редакцию.

robots.txt — дополнительный технический сигнал для обхода страниц, а не лицензия на контент. Опубликованные лимиты Partner API нельзя переносить на веб-выдачу. При отказах доступа сборщик должен останавливаться или увеличивать интервал, а не зависеть от постоянного обхода защит. [robots.txt OLX](https://www.olx.ua/robots.txt), [FAQ API](https://developer.olx.ua/ua/articles/faq).

Всю дальнейшую функциональность проектируем с заменяемым источником данных. Если стабильный допустимый доступ к выдаче не подтвердится, автоматический мониторинг считается нерешённым требованием; ручной импорт не выдаётся за его полноценную замену.

**4. Добавление поиска должно занимать несколько простых действий.**

1. Открыть бота, нажать «Старт» и отправить ссылку OLX либо вставить её в Mini App.
2. Получить предварительный разбор: категория, запрос, цена, регион и остальные распознанные параметры. Неподдерживаемые параметры видны отдельно.
3. Добавить собственные правила: нужные и запрещённые слова, требования к состоянию, описание задачи для ИИ.
4. Нажать «Проверить условия» и посмотреть небольшую выборку с объяснением, что проходит и что исключается. Такая проверка не включает регулярный мониторинг.
5. Выбрать поведение первого запуска, интервал и уведомления, затем включить поиск.

Если отправлена ссылка на одно объявление, бот объясняет различие и предлагает сохранить объявление или построить похожий поиск. Если ссылка некорректна, бот показывает понятную причину. Дублирование уже существующего поиска предлагает открыть его либо создать копию настроек.

**5. Mini App получает четыре основных экрана и подробную карточку поиска.**

| Экран | Основное содержимое |
|---|---|
| Поиски | Карточки поисков, активность, последнее успешное обновление, новые совпадения, пауза, проверка сейчас |
| Находки | Общая лента; фильтры по поиску, цене и статусу; сортировка по новизне и оценке |
| Избранное | Отложенные объявления, заметки, изменения цены, сохранённые фотографии |
| Настройки | Уведомления, тихие часы, OpenRouter, бюджет, хранение данных, экспорт |

Внутри поиска: исходная и текущая ссылка, фильтры OLX, собственные правила, ИИ, расписание, результат последней проверки. Подробный журнал открывается по необходимости. Основной экран не перегружается техническими полями.

Визуальное направление: компактные карточки с крупной ценой и фотографией, поддержка светлой/тёмной темы Telegram, заметные кнопки, нижняя навигация, раскрываемые настройки. Статусы обозначаются и цветом, и текстом. При закрытии Mini App мониторинг продолжает работать на сервере.

Карточка объявления показывает заголовок, цену, город, состояние, фотографии, полное сохранённое описание, причины соответствия, сомнения, время последней проверки и кнопку «Открыть в OLX». Отдельно различаются время публикации, время обнаружения и время сохранения.

Доступ к Mini App — через кнопку меню и профиль бота; из уведомления можно открыть конкретное объявление. Сервер проверяет подпись Telegram initData и свежесть авторизации. Регистрация отдельным паролем для личной версии не нужна. [Возможности и авторизация Mini Apps](https://core.telegram.org/bots/webapps).

**6. Ссылка и форма фильтров должны сохранять один и тот же смысл.**

На реальном интерфейсе OLX проверены следующие параметры. Здесь имена показаны в читаемом виде; в самой ссылке скобки и другие символы кодируются.

| Параметр URL | Значение в интерфейсе |
|---|---|
| currency=UAH | Валюта отображения и применяемого ценового фильтра в проверенной выдаче |
| search[filter_float_price:from]=1000 | Цена от 1 000 |
| search[filter_float_price:to]=10000 | Цена до 10 000 |
| search[private_business]=private | Частные продавцы |
| search[order]=created_at:desc | Самые новые |

Проверка сделана изменением фильтров в [выдаче электроники](https://www.olx.ua/uk/elektronika/). Это наблюдаемый формат сайта, а не обещание постоянного API-контракта.

Категория, город и поисковая фраза могут участвовать в пути ссылки; специальные фильтры зависят от категории. Поэтому нужен каталог поддерживаемых полей: тип, допустимые значения, зависимости, соответствие URL. При смене категории несовместимые поля предлагается убрать с явным объяснением.

Хранятся исходная ссылка, нормализованные параметры и актуальная пересобранная ссылка. Неизвестные фильтры сохраняются без редактирования, если их можно безопасно перенести в том же контексте. Если нельзя подтвердить их совместимость, интерфейс просит уточнить их значение; молча удалять их нельзя. Известные рекламные метки не участвуют в сравнении поисков. Номер страницы не становится постоянным ограничением мониторинга.

Нужны проверки обратимости: импорт → изменение одного поля → сборка ссылки → повторный импорт. Проверяется смысл фильтров, а не буквальное совпадение порядка параметров. После сохранения новой версии поиск запускается с её настройками; результаты старой версии не должны случайно породить новые уведомления.

Фильтры по описанию, запрещённые слова, ИИ и бюджет принадлежат боту. В URL OLX они не помещаются. Кнопка «Открыть поиск на OLX» воспроизводит только поддерживаемую OLX часть условий.

**7. Правила отбора делятся на обязательные условия и пожелания.**

| Группа | Возможности и поведение |
|---|---|
| Цена | Минимум/максимум, валюта, разрешение торга, политика для отсутствующей цены и обмена |
| Местоположение | Регион, город, радиус, исключение результатов за пределами заданной территории |
| Категория и характеристики | Состояние, тип товара, бренд, модель и проверенные поля конкретной категории |
| Продавец | Частный/бизнес; скрытие конкретного продавца при наличии устойчивого публичного идентификатора |
| Положительные слова | «Любое из», «Все группы», точная фраза; область проверки: заголовок, описание или оба |
| Отрицательные слова | Точное слово/фраза или смысловое условие; причина исключения сохраняется |
| Коммерческий шум | Аксессуары вместо устройства, запчасти, услуги ремонта, аренда, объявления «куплю», каталоги с условной ценой |
| ИИ-пожелания | Хорошая комплектация, предпочтительное состояние, соответствие свободному описанию задачи |

Пример логики: одна из фраз «steam deck»/«стим дек», плюс одна из «512»/«1 tb»; исключить продажу чехла. Числа и модификации сравниваются аккуратно: «3060» и «3060 Ti» — разные варианты, а совпадение короткой строки внутри другого слова не всегда считается совпадением.

Нормализация учитывает регистр, пробелы, украинский/русский/английский, распространённые варианты написания. Автоматическое расширение синонимов видно пользователю. Лексические фильтры и понимание смысла различаются: строгий запрет слова «ремонт» исключит и фразу «не был в ремонте»; смысловое правило «исключить ремонтированные» должно учитывать отрицание. В интерфейсе эти режимы нельзя смешивать.

Решение имеет три состояния: подходит, не подходит, недостаточно данных. Отсутствующее описание или неуказанная характеристика не считаются подтверждением хорошего состояния. Для обязательного условия с неизвестным значением — отдельная очередь сомнительных, если пользователь не выбрал другую политику.

Сначала применяются подтверждённые жёсткие ограничения. ИИ не может отменить максимальную цену или иной явный запрет. Пожелания влияют на сортировку, а не незаметно меняют обязательные условия.

Цены хранятся вместе с валютой и исходным текстом, без ошибок округления. Бесплатное, обмен, цена «от», первый взнос, цена за штуку и цена за комплект различаются. Значки доставки с «0 грн» не принимаются за стоимость товара. При конфликте цены в карточке и описании объявление помечается как неоднозначное. Стоимость доставки не добавляется как точное число, если её нет в данных.

**8. Рекламу нужно распознавать по её виду.**

Внешние баннеры и рекламные вставки не являются объявлениями и не попадают в базу товаров. Продвинутые карточки OLX — реальные объявления; для них нужен отдельный переключатель «Исключать продвинутые». Платное продвижение само по себе ничего не доказывает о выгодности предложения.

Объявления магазинов отсекаются собственным фильтром. Повтор одного товара в органической выдаче и в продвинутом блоке объединяется по ID. Рекомендации, похожие товары и результаты за пределами выбранной области не смешиваются с основной выдачей, если не включено расширение поиска.

При отсутствии надёжного признака продвижения хранится «неизвестно»; нельзя обещать стопроцентное удаление продвинутых карточек. Для строгого режима пользователь выбирает, пропускать ли такие неопределённые случаи.

**9. Сбор идёт по расписанию и экономит повторные обращения.**

Предпочтительный способ чтения после решения вопроса доступа — обычные публичные страницы и доступные в них структурированные данные. Браузерный движок рассматривается, если часть страницы действительно требует выполнения JavaScript. Внутренние неофициальные запросы сайта не становятся гарантированной основой проекта. Способ выбирается по результатам отдельной проверки.

Порядок одного прохода:

1. Планировщик выбирает активный поиск и фиксирует версию его условий. Одновременно два прохода одного поиска не запускаются.
2. Загружается выдача с проверенной сортировкой по новизне. Сохраняется информация о ходе обхода.
3. Выделяются именно объявления: ID, ссылка, заголовок, цена, доступные характеристики, признаки продвижения.
4. Для всех встреченных объявлений обновляются минимальные записи присутствия в базе, включая отклонённые.
5. Применяются однозначные дешёвые фильтры. Если условие зависит от описания, отсутствие слова в заголовке ещё не является причиной отклонения.
6. Для оставшихся кандидатов загружается полное описание и данные карточки либо используется достаточно свежая сохранённая версия.
7. Выполняются правила по описанию и, при включении, ИИ-проверка. Ошибка получения данных не превращается в отрицательное решение.
8. Подходящее объявление и результат отбора сохраняются. Загружаются фотографии; запись и событие на отправку согласуются через базу.
9. Проверяются права на уведомление, тихие часы, история доставок и другие совпавшие поиски.
10. Отправляется карточка, записывается результат доставки; проход получает статус полного, частичного или ошибочного.

При первом запуске можно обойти все доступные страницы в пределах согласованного бюджета. Затем чаще проверяются первые страницы с перекрытием уже просмотренного участка. Встреча одного знакомого ID не останавливает обход: выше и ниже могут находиться новые объявления, а старые поднимаются и продвигаются.

Глубина зависит от скорости появления предложений. Если новые объявления уходят глубже проверяемого диапазона, интерфейс показывает риск пропуска и предлагает сузить поиск, увеличить глубину или изменить интервал в пределах допустимой нагрузки. После простоя запускается восстановительный проход. Периодическая более глубокая сверка помогает находить изменения старых карточек, но не гарантирует увидеть объявление, появившееся и исчезнувшее между проверками.

«Все объявления» означает доступные результаты конкретного поиска на момент обхода. У большой выдачи могут быть пределы пагинации, рекомендации и изменения между страницами. Поэтому показываются проверенные страницы, время и полнота покрытия, а не неподтверждённая надпись «обработано всё».

Стартовый интервал для пилота предлагается 10–15 минут, с пересмотром после измерений. Это не известный разрешённый лимит OLX. Для 10 разных поисков, двух страниц и интервала 15 минут получается 1 920 загрузок страниц выдачи в сутки, ещё до описаний и фото. Частота должна рассчитываться по общей нагрузке, а не только по одной ссылке.

Нужны общий ограничитель запросов к OLX, очередность между поисками, увеличивающиеся задержки при ошибках и соблюдение Retry-After, если он передан. Совпадающие выдачи и свежие подробности одного объявления по возможности загружаются один раз. ИИ и обработка изображений могут выполняться параллельно в своих лимитах; число поисков не означает такое же число одновременных запросов к OLX.

**10. База отличает увиденное объявление от отправленного уведомления.**

| Сущность | Что хранит |
|---|---|
| Пользователь | Telegram ID, часовой пояс, доступ, настройки уведомлений |
| Поиск | Название, ссылки, фильтры, версия, расписание, активность, бюджет |
| Объявление | Площадка/регион + устойчивый OLX ID, каноническая ссылка, актуальные данные |
| Версия объявления | Изменения цены, описания, характеристик и контрольные отпечатки содержимого |
| Присутствие в поиске | Когда впервые/последний раз встречено, при какой версии условий |
| Решение фильтров | Подходит/нет/неясно, причины, версия объявления и правил |
| ИИ-проверка | Модель, версия запроса, результат, доказательства, токены и стоимость |
| Медиа | Путь к сохранённому файлу, источник, размер, контрольная сумма, Telegram file_id |
| Отправка | Событие, получатель, попытки, состояние, Telegram message_id |
| Проход поиска | Покрытие, счётчики, длительность, ошибки, контрольная точка |
| Действия владельца | Избранное, скрытое, заметки, обратная связь |

Минимальные данные об отклонённых объявлениях нужны, чтобы не тратить запросы и деньги повторно. Их фотографии обычно не скачиваются. Полный архив и изображения предназначены для подходящих и избранных объявлений, с учётом согласованных прав использования и политики хранения.

Основной ключ дедупликации — регион OLX и устойчивый ID, а не заголовок, цена или вся ссылка. Одна карточка может совпасть с несколькими поисками; в ленте она связывается со всеми ними, а в один Telegram-чат по умолчанию приходит одно первичное уведомление. Новый поиск не должен быть заблокирован тем, что товар когда-то был отклонён в другом поиске.

Перепубликация с другим ID — отдельный случай. Позже можно находить вероятные повторы по продавцу, характеристикам, тексту и сходству фотографий. По одному похожему заголовку автоматически скрывать объявления нельзя; по умолчанию такое сходство только помечается.

**11. Первый запуск, изменение фильтров и изменения товара имеют разные правила.**

Первый запуск по умолчанию формирует исходный список без отправки сотен карточек. Подходящие существующие предложения доступны в Mini App, а бот присылает итог количества. Альтернативы: отправить лучшие N либо все найденные с ограничением темпа. Выбор делается при включении поиска.

Во время исходного обхода новые объявления могут появляться параллельно. Нужны фиксация времени начала и повторная проверка начала выдачи после обхода, чтобы не потерять этот промежуток. Если точное время публикации неизвестно, система называет запись «впервые обнаружено», а не утверждает, что товар только что опубликован.

| Событие | Предлагаемое поведение |
|---|---|
| Ранее не встреченное подходящее объявление после исходного обхода | Сохранить и уведомить |
| Уже отправленное без существенных изменений | Повторно не отправлять |
| То же объявление найдено другим поиском | Добавить связь с поиском; не дублировать сообщение |
| Ранее не подходило, но цена/описание изменились и теперь подходит | Отдельное событие «теперь соответствует», если включено |
| Снизилась цена уже отправленного | Отправить уведомление о скидке: старая и новая цена, размер скидки в гривнах и процентах, ссылка на OLX; срабатывает при заданном пороге в гривнах или процентах |
| Владелец изменил фильтры | Пересчитать доступный архив; старые совпадения показать отдельно, массовую рассылку не начинать автоматически |
| Ручная «Проверить сейчас» | Обновить поиск без сброса истории отправок |
| Пауза, перезапуск сервера, восстановление связи | Сохранить историю и продолжить с контрольной точки |

Исчезновение из поисковой выдачи не доказывает продажу. Отдельно различаются «не встретилось», «недоступно при проверке» и явно подтверждённое состояние страницы. После ошибки сети объявление нельзя помечать проданным.

Для очистки мусорных данных вводится отдельная проверка актуальности сохранённых объявлений. По расписанию бот обращается к прямой ссылке: если страница действительно недоступна или объявление снято, он повторяет проверку через заданную задержку. Если недоступность подтверждена повторно, полностью удаляются объявление, его сохранённые описания, фотографии, результаты ИИ, связи с поисками, избранное, заметки и записи уведомлений. В приложении оно исчезает. Не остаётся даже записи-ID, поэтому вернувшееся или повторно опубликованное объявление считается новым. Временная ошибка сети, блокировка, изменение структуры страницы или единичный неудачный ответ не запускают удаление.

**12. ИИ анализирует кандидатов, а настройки задаются на уровне каждого поиска.**

В личной версии достаточно одного серверного ключа OpenRouter. Для каждого поиска выбираются модель, инструкция, режим проверки, разрешённая резервная модель и бюджет. Отдельный ключ на каждую ссылку технически возможен, но обычно избыточен. При нескольких владельцах ключи и расходы должны быть изолированы.

Предлагаемые режимы: ИИ выключен; ИИ для неоднозначных кандидатов; ИИ для каждого кандидата, прошедшего обычные фильтры. Режим выбирается исходя из требований: если обязательное смысловое условие нельзя проверить правилами, соответствующие кандидаты обязательно проходят ИИ.

Пример пользовательской инструкции: «Нужна полностью рабочая консоль, без блокировок аккаунта и дефектов экрана. Исключить аксессуары и объявления о ремонте. Небольшие царапины корпуса допустимы. Если состояние не описано — отправить в сомнительные».

Модель получает очищенный заголовок, описание, доступные характеристики, цену и требования. Она возвращает решение, извлечённые свойства, выполненные/нарушенные условия, неизвестные сведения и короткое объяснение с фрагментами исходного текста. Значение «неизвестно» обязательно. Числовую уверенность модели нельзя показывать как измеренную вероятность исправности товара.

Отдельный режим ИИ оценивает ценность предложения для твоей задачи. Он выдаёт понятную метку «очень интересно / интересно / обычно / сомнительно» и объясняет её: соответствие требованиям, комплектация, риски из описания, состояние и отклонение цены от доступного ориентира. Эта оценка видна в карточке находки и в списке Mini App, позволяет сортировать предложения и показывается в Telegram-уведомлении. Она не является обещанием рыночной цены, прибыльности или отсутствия мошенничества.

Ответ запрашивается по строгой схеме, затем проверяется сервером. Требуется совместимый провайдер; некорректный ответ приводит к ограниченному повтору или статусу «проверка не завершена». Структурированный формат ограничивает форму ответа, но не гарантирует истинность выводов. [Structured Outputs](https://openrouter.ai/docs/guides/features/structured-outputs), [выбор поддерживающего провайдера](https://openrouter.ai/docs/guides/routing/provider-selection).

Текст продавца — данные, а не команды. Модель не получает инструменты управления ботом, ключи, историю чата или возможность переходить по произвольным ссылкам из описания. Фразы вроде «игнорируй требования» внутри объявления не должны влиять на правила оценки. Подтверждающие фрагменты сверяются с полученным текстом.

Экономия: ИИ вызывается после дешёвых фильтров; результат повторно используется только при совпадении значимых данных объявления, версии условий, инструкции и модели. Изменившаяся цена должна учитываться, если она влияет на решение. Дорогая резервная модель запускается только по заранее разрешённому сценарию и в пределах лимита. Автоматическая подмена на более дорогую модель без ограничений не нужна.

Если OpenRouter недоступен или бюджет закончился, обычный сбор продолжается. Объявления с обязательной ИИ-проверкой остаются ожидающими, а не объявляются подходящими. Отправка «без ИИ» — отдельная настройка, явно отмеченная в уведомлении. Нужны дневной и месячный лимиты с резервированием бюджета перед параллельными запросами и учётом повторов.

Перед внешней обработкой удаляются ненужные телефоны и контактные данные. Настройки хранения у OpenRouter и конечного провайдера проверяются отдельно; можно ограничивать маршрутизацию по политике данных. Это не заменяет решение вопроса прав на исходный контент. [Политика данных OpenRouter](https://openrouter.ai/docs/guides/privacy/data-collection).

Для старта стоит испытать Gemini 2.5 Flash-Lite как дешёвого кандидата, затем сравнить ещё одну бюджетную модель на одинаковых объявлениях. Окончательный выбор — по украинским и русским описаниям, ошибкам отбора и стоимости, а не по одному общему рейтингу. Анализ фотографий ИИ оставить на следующий этап и включать только по необходимости.

**13. «Подходит» и «выгодно» — разные оценки.**

В первой версии выгодность выражается через понятные пользовательские условия: желаемая цена, комплектация и состояние. ИИ объединяет эти факторы в объясняемую оценку ценности, но не должен выдумывать рыночную стоимость по памяти.

Позже можно рассчитывать ориентир по сохранённым сопоставимым предложениям: одна модель/модификация, похожее состояние, комплект, регион и близкий период. Исключаются условные цены, запчасти, повторы и выбросы. В карточке показываются размер выборки, её свежесть, ориентир и отличие цены.

При малой выборке вывод — «недостаточно данных о рынке»: ИИ всё ещё может показать соответствие твоим требованиям и риски, но не называет предложение выгодным по цене. Цены опубликованных объявлений не равны ценам состоявшихся сделок. Метка выгодности означает соответствие расчётному ориентиру, а не гарантию качества, честности продавца или прибыли.

**14. Фотографии сначала сохраняются в хранилище бота, затем отправляются в Telegram.**

После положительного решения скачиваются доступные фотографии объявления с ограничением числа, размера и времени загрузки. Файлы проверяются по формату, при необходимости подготавливается уменьшенная версия для Telegram. Полная доступная копия хранится отдельно; это не обязательно исходник камеры продавца.

Для первой версии: до 10 изображений на подходящее объявление; обложка отправляется сразу, остальные доступны в Mini App или по кнопке «Фото». Альбом — альтернативный режим уведомления. В базе остаются связь с объявлением, контрольная сумма и состояние загрузки каждой фотографии.

Если фотография не загрузилась, полезное объявление не теряется: бот может прислать текстовую карточку с отметкой о фото и повторить загрузку позже. При строгом режиме архивации отправка ждёт хотя бы обложку с ограниченным таймаутом. Не следует задерживать уведомление бесконечно из-за последнего изображения.

Telegram позволяет отправлять фото загрузкой файла и повторно использовать file_id. Альбом sendMediaGroup содержит 2–10 элементов; у самого метода нет reply_markup, поэтому кнопки размещаются отдельным сообщением. Подпись к фото ограничена 1 024 символами — полное описание остаётся в Mini App или выдаётся отдельным текстом. [Bot API](https://core.telegram.org/bots/api#sendphoto), [альбомы](https://core.telegram.org/bots/api#sendmediagroup).

Telegram file_id служит кэшем повторной отправки, но независимое хранилище необходимо для архива и галереи Mini App. Нельзя отдавать клиенту URL Telegram, содержащий токен бота. После удаления объявления из OLX локальная сохранённая копия может оставаться до окончания выбранного срока хранения.

**15. Уведомление должно позволять быстро решить, открывать ли товар.**

Предлагаемый пример карточки, все данные в нём условные:

> Steam Deck 512 GB — 11 500 грн
>
> Львов · б/у · впервые обнаружено в 14:32
>
> Подходит: нужная модель, цена в пределах бюджета.
>
> Оценка ИИ: интересно — цена ниже ориентира, комплект подтверждён; состояние аккумулятора не указано.
>
> Из описания: продавец указывает исправную работу; есть зарядка.
>
> Не уточнено: состояние аккумулятора.
>
> Поиск: «Консоль до 12 000»

Кнопки: «Открыть в OLX», «Подробнее», «В избранное», «Скрыть». Просмотр галереи и объяснения ИИ — в подробной карточке. Кнопка OLX ведёт на исходное объявление; оформление покупки пользователь завершает в OLX.

Настройки: сразу или дайджестом; тихие часы; уведомления по выбранным поискам; максимальное количество сообщений за период; отдельные события снижения цены. При окончании тихих часов можно прислать сводку вместо десятков сообщений. Интерфейс показывает очередь ожидающих отправок.

Отправки проходят через постоянную очередь с уникальным ключом события, чтобы параллельные задачи и перезапуски не создавали обычных дублей. Учитываются лимиты Telegram и задержка retry_after при 429. Для одного чата следует избегать темпа выше одного сообщения в секунду. [Telegram FAQ](https://core.telegram.org/bots/faq#my-bot-is-hitting-limits-how-do-i-avoid-this).

Абсолютное «ровно один раз» при сетевом сбое обещать нельзя: Telegram мог принять сообщение, а ответ не дошёл до сервера. Для этого случая нужен отдельный статус «доставка не подтверждена». Для личной версии предлагается не повторять такую отправку автоматически: находка остаётся в Mini App с возможностью ручной повторной отправки. Подтверждённые временные отказы повторяются ограниченно; подтверждённые успехи сохраняются по message_id.

**16. Для первой версии достаточно одного развёртывания с отдельными фоновыми процессами.**

Предлагаемый стек — инженерный выбор для этого проекта, а не обязательное условие:

| Часть | Предложение | Причина |
|---|---|---|
| Mini App | React + TypeScript | Удобная форма фильтров, галерея и мобильный интерфейс |
| Сервер приложения | Python + FastAPI | API интерфейса, проверка данных и управление поисками |
| Telegram | aiogram | Получение команд, кнопки и отправка уведомлений |
| Сборщик | HTTP-клиент и HTML-парсер; Playwright при обоснованной необходимости | Получение выдачи и подробностей отдельно от интерфейса |
| База | PostgreSQL | Связи, история, уникальные ограничения и согласованные записи |
| Фоновые задачи | Celery + Redis | Очереди сборки, ИИ, медиа и уведомлений |
| Фотографии | Каталог на постоянном диске; S3-совместимое хранилище при росте | Независимый архив с возможностью сменить способ хранения |
| Развёртывание | Docker Compose на VPS, HTTPS, резервное копирование | Один управляемый комплект сервисов для личного использования |

Роли выбранных инструментов сверены с [FastAPI](https://fastapi.tiangolo.com/), [aiogram](https://docs.aiogram.dev/), [Celery](https://docs.celeryq.dev/en/stable/) и [Playwright](https://playwright.dev/python/). Конкретные версии фиксируются при реализации после проверки совместимости.

База — источник истины о проходах и отправках; очередь ускоряет выполнение. Потеря Redis не должна стирать найденные товары или создавать повторную массовую рассылку: незавершённые задания восстанавливаются по состояниям в PostgreSQL. Не нужны Kubernetes, отдельные микросервисы на каждый поиск и векторная база для первой версии.

Пилотный сервер: ориентир 2 vCPU и 4 GB RAM с пересмотром после измерений. Это предположение о ресурсах, не результат нагрузки. Для постоянного браузерного сбора может понадобиться больше памяти. Домашний компьютер подходит для локальной отладки, но при сне, выключении или пропадании связи проверки останавливаются.

**17. Секреты, хранение и диагностика входят в основную работу бота.**

Ключи Telegram и OpenRouter находятся только на сервере, не попадают в сообщения, браузерный код и журналы. В личной версии доступ ограничен Telegram ID владельца. При расширении на несколько пользователей каждая операция проверяет владельца поиска, результата, бюджета и медиа.

Импорт ссылок разрешает только поддерживаемые домены и типы страниц; редиректы тоже проверяются. Запрещаются обращения к локальным и служебным адресам сервера. Для фотографий используются проверенные источники из данных OLX и ограничения скачивания. Текст объявления экранируется перед показом, произвольный HTML не исполняется.

Предлагаемое хранение: фото обычных находок 30 дней, текст и решения 90 дней; избранное — до удаления владельцем в рамках установленного лимита. Отдельная проверка актуальности удаляет все данные объявления раньше этого срока после подтверждённой недоступности его ссылки. Для существующих объявлений ID и история отправок хранятся, пока активен поиск, чтобы очистка фото не создавала повторные уведомления. Сроки настраиваются; после удаления старого описания пересмотр его условий может требовать нового получения страницы.

Нужны ежедневные резервные копии базы, отдельная копия важных фото и проверка восстановления. Минимальная цель пилота: потеря не более суток архивных данных при полной аварии и ручное восстановление в течение рабочего дня; более строгая цель потребует другого резервирования.

Экспорт: CSV с находками и ссылками, полный структурированный экспорт настроек и результатов, отдельный архив изображений по запросу. Экспорт не включает секреты. Удаление поиска сначала останавливает задания; общие объявления не удаляются, пока связаны с другим поиском или избранным.

Диагностика измеряет время последнего успешного прохода, глубину проверки, количество новых/отклонённых/сомнительных, ошибки получения, расходы ИИ, место под фото и возраст очереди. Неожиданное исчезновение всех карточек или цен — ошибка структуры, а не «новых предложений нет». Пользователь получает уведомление о длительной остановке и о восстановлении, без сообщения на каждую краткую ошибку.

**18. Стоимость рассчитывается по реальной нагрузке и ограничивается настройками.**

На дату исследования карточка Gemini 2.5 Flash-Lite в OpenRouter показывает стандартную цену $0.10 за миллион входных токенов и $0.40 за миллион выходных. Тариф зависит от выбранного маршрута и может измениться; это кандидат для испытаний. [Цена модели](https://openrouter.ai/google/gemini-2.5-flash-lite).

При условных 1 500 входных токенов и 150 выходных на одно объявление один анализ стоит примерно $0.00021; тысяча анализов — $0.21; 30 000 — $6.30. Это расчёт одного текстового вызова на объявление, включая условия в указанном входном объёме. Повторы, повторная оценка по другим поискам, длинные описания, дополнительные модели, фотографии, комиссии пополнения и налоги в эту сумму не включены.

Расход на ИИ зависит от количества новых кандидатов, прошедших обычные фильтры, а не непосредственно от числа проверок ссылок. В интерфейсе показываются фактическая стоимость и прогноз с указанием допущений.

Для планирования можно заложить резерв $10–25 в месяц на небольшой сервер и резервное хранение плюс отдельный лимит ИИ $2–10. Это бюджетная гипотеза, не проверенное коммерческое предложение хостинга. Домен, большой архив и постоянный браузерный сбор могут увеличить сумму. Окончательная инфраструктурная смета составляется после проверки источника и недельного пилота.

Пример ёмкости архива: 100 сохранённых объявлений в день × 6 фото × 200 KB × 30 дней ≈ 3.6 GB, без резервной копии и оригиналов большего размера. При 1 000 объявлениях в день — около 36 GB. Поэтому хранить изображения каждого отклонённого товара не нужно.

**19. Реализация должна идти через проверяемые этапы.**

| Этап | Что делается после разрешения на разработку | Результат и условие перехода |
|---|---|---|
| 0. Источник и границы | Уточнить условия доступа/контента, получить 3–5 целевых ссылок, проверить выдачу, детали, фото, сортировку, пагинацию и доступ с сервера | Подтверждённый способ получения данных либо зафиксированный блокер; список поддерживаемых категорий |
| 1. Основа мониторинга | Один поиск целиком: импорт, сбор, описание, правила, база, повторный проход, очередь отправки | Новый подходящий товар проходит весь путь; старый не присылается повторно |
| 2. Mini App и несколько поисков | Основные экраны, редактирование URL/фильтров, расписания, пауза, общая лента, первый запуск | Несколько независимых поисков управляются из Telegram |
| 3. Архив и уведомления | Фото, file_id, галерея, избранное, тихие часы, восстановление после сбоев | Сохранённое объявление доступно независимо от страницы OLX; проверена доставка |
| 4. OpenRouter | Настройка по поискам, строгий ответ, неизвестные значения, кэш, ограничения затрат | Смысловой отбор проверен на вручную размеченной выборке |
| 5. Пилот | 7–14 дней с целевыми поисками, контроль пропусков, шума, запросов, бюджета и восстановления | Есть измерения стабильности и скорректированные интервалы |
| 6. Расширение | Снижение цены, вероятные перепубликации, сравнение цен, дополнительные категории, ИИ по фото | Добавляется по результатам использования |

Предварительная трудоёмкость для одного разработчика: этап 0 — 2–4 рабочих дня технической проверки без ожидания внешних согласований; основа — 4–7; Mini App — 5–8; архив и надёжность — 3–5; ИИ — 3–5. Всего около 17–29 рабочих дней после успешной проверки источника, затем период пилота. Это ориентир для планирования; неизвестные ограничения OLX могут изменить и сроки, и допустимый объём проекта.

Полезная первая версия включает всё основное из запроса: несколько ссылок, Mini App, проверенные редактируемые фильтры, ключевые слова и описания, базу, новые уведомления, фотографии, прямую ссылку OLX и необязательный ИИ для каждого поиска. Рыночная аналитика, сложное распознавание перепубликаций и анализ фото ИИ идут позже.

**20. Готовность проверяется по поведению, а не только по наличию экранов.**

| Сценарий | Ожидаемый результат |
|---|---|
| Импорт целевой ссылки | Все поддерживаемые фильтры распознаны, неизвестные видны |
| Изменение цены/региона/сортировки | Полученная ссылка воспроизводит выбранные условия |
| Положительное слово только в описании | Объявление проверяется по описанию и не теряется на заголовке |
| Отрицание «не был в ремонте» | Строгий и смысловой режимы ведут себя согласно выбранной настройке |
| Посторонняя модель в списке ключевых слов | ИИ не принимает её автоматически за продаваемый товар |
| Рекламный баннер и продвинутая карточка | Баннер исключён; карточка обрабатывается согласно переключателю |
| Одинаковый ID в нескольких поисках | Одна запись товара, несколько совпадений, одно первичное сообщение в чат |
| Первый обход большой выдачи | Старые карточки не создают непрошеную массовую рассылку; видна полнота обхода |
| Перезапуск фонового процесса | История не теряется, подтверждённые отправки не повторяются |
| Сетевой таймаут отправки | Нет ложного подтверждения доставки; применяется выбранная политика неопределённости |
| Изменение фильтров во время прохода | Устаревшие решения не отправляются как результаты новых правил |
| Недоступное описание, ИИ или превышение бюджета | Видимый статус ожидания/неопределённости, без ложного «подходит» |
| Дважды подтверждённая недоступность страницы OLX | Полностью удаляются карточка, фото, описание, связи, ИИ-оценки, избранное и история уведомления; в Mini App объявления больше нет |
| Единичный сбой при проверке страницы OLX | Данные не удаляются; страница проверяется повторно |
| Изменение структуры сайта | Поиск показывает ошибку и не изображает успешную пустую проверку |
| Восстановление из резервной копии | Поиски, находки и история отправок возвращаются согласованно |

Для смысловой оценки нужна выборка порядка 150–300 объявлений с ручной разметкой, включая украинский/русский текст, отрицания, условные цены, запчасти и рекламные перечни моделей. Отдельно измеряются доля подходящих среди уведомлений и доля найденных среди известных подходящих в контрольной выборке. Начальная цель для узкой категории — не менее 90% корректных уведомлений; требование к полноте согласуется с допустимым шумом. Эти показатели не заявляются достигнутыми до испытаний и не доказывают охват всего OLX.

Для задержки цель пилота: при доступном источнике и ненасыщенной очереди 95% обнаруженных совпадений доставляются не позже одного настроенного интервала плюс две минуты обработки. Это цель измерения, а не обещание задержки от реального момента публикации, который не всегда известен.

**21. Начальные решения можно принять без усложнения первой версии.**

Предлагаемые значения по умолчанию: один владелец; OLX.ua; до 5–10 узких поисков на пилоте; интервал 15 минут с корректировкой; первый обход без отдельных уведомлений; баннеры исключаются; продвинутые объявления обрабатываются как обычные с возможностью отключения; одна обложка в сообщении; остальные фото в галерее; сомнительные объявления — отдельной вкладкой; ИИ включается отдельно на каждом поиске; снижение цены присылается при скидке от 5% или от выбранной владельцем суммы; повторные публикации не создают уведомления без включения соответствующего режима; подтверждённо недоступные объявления удаляются вместе со всеми связанными данными.

Перед разработкой желательно уточнить только то, что реально меняет объём: личный или многопользовательский бот, 3–5 примеров целевых поисков, допустимая задержка, первоначальные категории и месячный предел расходов. Эти уточнения не мешают проработке концепции. Отдельное внешнее условие — подтверждение способа доступа и использования данных OLX.

В текущем этапе создан только этот проектный документ. Бот не зарегистрирован, ключи не запрашивались, фоновые проверки и платные вызовы не запускались.

## Начало промпта

Ты разрабатываешь **OLX Hunter** — личный Telegram-бот с Mini App для наблюдения за поисковыми выдачами OLX.ua. Создай работающий репозиторий целиком: интерфейс, API, бот, сборщик, фоновые задания, базу, фотографии, интеграцию OpenRouter, тесты основных рисков и запуск через Docker Compose. Пользователь должен заполнить внешние реквизиты и запустить готовый комплект; не перекладывай на него написание кода, проектирование базы или соединение частей.

Не заканчивай на макете, плане работ, заглушках или перечислении файлов. Реализуй доступное, проверь основные сценарии и явно назови только оставшиеся внешние зависимости. Если рабочий доступ к OLX не подтверждён, заверши остальные части и адаптер, но честно отметь мониторинг как неподтверждённый: тестовые данные не доказывают живой сбор. Не изображай локальный тест как недельный пилот.

### 1. Продукт и границы первой сборки

Владелец отправляет ссылку на выдачу OLX, редактирует распознанные фильтры, добавляет правила по тексту и при необходимости ИИ-инструкцию. Сервер проверяет несколько поисков по расписанию, сохраняет подходящие товары с фотографиями и отправляет новые совпадения в личный чат Telegram. Находка открывается в Mini App, покупка — по прямой ссылке в OLX.

По умолчанию один владелец, OLX.ua, русский интерфейс, `Europe/Kyiv`, валюта UAH. Строки интерфейса вынеси в словарь, чтобы позже добавить украинский без переписывания компонентов. Все времена в БД — UTC, пользователю показывай местные. Поддержка пользователей в схеме нужна для изоляции данных, но регистрацию, тарифы и публичную админку не создавай.

Обязательны: несколько поисков; импорт/сборка ссылок; редактируемые проверенные параметры OLX; цена и ключевые слова; анализ полного описания; регулярные проверки; история ID; независимые правила на поиск; общая лента без дублей; сохранённые и скрытые; локальные фото; Telegram-уведомления; OpenRouter на уровне поиска; контроль расходов; падение цены; очистка подтверждённо снятых объявлений; экспорт и резервные копии.

Не добавляй: внутренний чат с продавцом, оплату, покупку внутри бота, карту, рекомендации без запроса, NFT, геймификацию, рейтинги пользователей, аккаунт с паролем, социальную ленту, рекламную главную страницу, календарь, отдельную страницу статистики, отдельный раздел моделей. Не добавляй функциональность только потому, что для неё есть готовый UI-компонент.

### 2. Фиксированный стек и устройство репозитория

| Слой | Инструменты | Назначение |
|---|---|---|
| Mini App | React, TypeScript, Vite | Одно клиентское приложение без SSR |
| Оформление | Tailwind CSS, shadcn/ui, Lucide | Собственные лаконичные токены, доступные компоненты и одинаковые иконки |

| API | Python, FastAPI, Pydantic | Авторизация, команды и сериализация |
| Telegram-бот | aiogram | Входящие ссылки, открытие приложения, уведомления |
| Данные | PostgreSQL, SQLAlchemy, Alembic | Транзакции, версии правил, журнал отправок |
| Фон | Celery, Redis | Очереди сбора, анализа, медиа и доставки |

Закрепи конкретные совместимые версии в lock-файлах на момент реализации. Структура: `frontend/`, `backend/app/`, `backend/migrations/`, `backend/tests/`, `tests/e2e/`, `infra/`, `scripts/`, `docs/`. В backend раздели `api`, `bot`, `sources`, `filters`, `ai`, `media`, `jobs`, `notifications`, `models`, `services`. Общую бизнес-логику вызывают и бот, и API: не реализуй две разные версии импорта ссылки.

Сервисы Compose: `gateway`, `api`, `bot`, `worker`, `scheduler`, `postgres`, `redis`. Для первой личной установки бот использует long polling, поэтому Telegram webhook не является обязательной дополнительной настройкой. По одному процессу планировщика; транзакционные блокировки должны защищать от случайного второго экземпляра.

### 3. Что остаётся внешним, а что нужно подготовить автоматически

Подготовь `.env.example` и `scripts/setup`, который объясняет поля, проверяет значения, создаёт внутренние случайные секреты и защищённый `.env`, затем проверяет конфигурацию. Не выводи секреты в журнал. Не проси владельца вручную создавать таблицы, секрет сессии, папки медиа или Redis-очереди.

| Поле/условие | Кто предоставляет | Поведение без него |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | Владелец получает в BotFather | Живой Telegram не запускается; API и тестовый режим доступны |
| `OWNER_TELEGRAM_ID` | Владелец | Внешний доступ закрыт, по первому посетителю владение не назначается |
| `PUBLIC_BASE_URL` / домен и сервер | Владелец предоставляет доступное HTTPS-размещение | Локальная разработка возможна; мобильный Mini App не объявляй готовым к внешнему запуску |
| `OPENROUTER_API_KEY` | Владелец, только если нужен ИИ | Обычные фильтры и мониторинг работают; ИИ выключен |
| Допустимый рабочий источник OLX | Подтверждённый способ доступа; при необходимости внешние реквизиты | Статус «Источник не настроен/недоступен»; не фабрикуй результаты |

Внутренние значения: `DATABASE_URL`, `REDIS_URL`, `SESSION_SECRET`, каталог медиа, интервалы и лимиты. Сгенерируй шаблон корректных URL базы и Redis из Compose. `BOT_USERNAME` и возможности бота проверяй через `getMe`; короткое имя Mini App — через внешнюю настройку BotFather, если выбран такой способ deep link. Подготовь проверяемые ссылки открытия и памятку BotFather: меню, Main Mini App и HTTPS-адрес. Регистрацию бота и владение доменом нельзя выдумать или «автоматически» выполнить без доступа к соответствующим аккаунтам.

Покажи точные команды локального запуска, production-запуска, миграций, диагностики, бэкапа и восстановления. Генерацию `.env` делай с правами `0600`; `.env`, дампы и ключи исключи из Git.

### 4. Источник OLX и преобразование ссылок

Введи интерфейс `ListingSource` с операциями: `parse_search_url`, `build_search_url`, `fetch_search_page`, `fetch_listing`, `check_availability`. Ответ включает данные и признак полноты/ошибки. Раздели сетевую загрузку и чистый разбор документа: парсер должен проверяться на локальных фикстурах.

Разреши только OLX.ua и подтверждённые относящиеся к нему хосты. Проверяй тип страницы, DNS/IP, цепочку перенаправлений и адрес назначения; закрой обращения к localhost, частным и служебным адресам. Для медиа используй отдельно проверенный список источников, не обрабатывай любой URL из текста продавца. Ограничь время, объём ответа, число перенаправлений и размер распакованного тела.

Начни с HTTP и доступных структурированных данных/HTML. Браузерный сбор добавляй только после доказанной необходимости, отдельной зависимостью. Не основывай продукт на постоянном обходе CAPTCHA, вращении аккаунтов или сокрытии нагрузки. Отказы доступа — отдельное состояние и backoff; они не являются пустой выдачей или подтверждением удаления.

Создай реестр полей фильтров: категория, тип поля, подпись, допустимые значения, зависимости, соответствие пути/параметру URL, поддержка чтения/редактирования/сборки. Значения категорий и городов не придумывай. Неизвестный фильтр хранится как исходный параметр и показывается под «Дополнительно»; если безопасное перенесение в изменённый контекст не подтверждено, блокируй сохранение именно этой несовместимой конфигурации и объясни выбор.

Храни `original_url`, нормализованную спецификацию, непрозрачные параметры и `current_url`. Сервер — единственный источник преобразования ссылок. Текстовые правила, ИИ и расписание не добавляй в URL OLX. Убирай лишь известные tracking-метки; `page` становится параметром текущего обхода, а не постоянным фильтром. Дубликат поиска определяй по нормализованным OLX-условиям и правилам бота, а не по порядку query-параметров. Для одинакового URL с другими текстовыми правилами разреши отдельный поиск.

Импорт выдачи создаёт черновик; запуск начинается только по основному действию владельца. Импорт отдельного объявления создаёт черновик сохранения одной карточки и не включает неявный мониторинг всей категории.

### 5. Предметная модель и ограничения БД

| Сущность | Ключевые данные |
|---|---|
| `users` | Telegram ID с unique, timezone, доступ и глобальные настройки |
| `searches` | owner, название, ссылки, active, revision, правила, режим ИИ, расписание, настройки событий |
| `search_drafts` | owner, исходная ссылка, черновик, срок жизни; чат и приложение открывают один черновик |
| `listings` | source + market + устойчивый ID с unique, URL, текущая версия, first/last seen |
| `listing_versions` | Хэш значимых данных, цена/валюта, текст, свойства, даты |
| `search_matches` | Поиск + объявление, revision, версия объявления, решение, причины, first/last seen |
| `user_listing_state` | owner + объявление с unique; saved, hidden, seen, note |
| `ai_evaluations` | Ключ кэша, схема/модель/инструкция, решение, доказательства, usage, стоимость/статус |
| `media` | Объявление, checksum, безопасный путь, размеры, порядок, статус, Telegram file_id |
| `scan_runs` | Поиск, revision, lease/fencing token, статус, охват, счётчики, даты, ошибка |
| `notification_events` | Событие для owner + объявления, тип, ревизии/версия цены, уникальный dedup-key |
| `delivery_attempts` | Канал/чат, событие, статус, message_id, retry_after, неопределённая доставка |
| `budget_ledger` | Период, owner/search, резерв, фактические расходы и неопределённые начисления |
| `export_jobs` | owner, формат, статус, временный файл и срок доступности |

Цена — `Decimal`/NUMERIC, никогда float. Храни валюту и исходный ценовой текст. Отличай обычную цену, бесплатно, обмен, «от», рассрочку/первый взнос и цену комплекта. `0` не означает «не указано». Не вычисляй скидку между разными валютами или несопоставимыми типами цены.

ID бери из подтверждённых данных площадки. Если встречаются разные представления одного ID в URL и документе, преобразование должно быть проверено; не дедуплицируй по заголовку или попытке угадать числовой ID.

Добавь внешние ключи, каскад удаления для данных объявления, индексы по owner, active, next_run_at, listing_id, статусам очередей и времени. Уникальные ограничения обеспечивают дедупликацию при гонках. Медиафайл может разделяться по checksum: удаление ссылки одного объявления не должно уничтожить файл, используемый другим.

Потеря Redis восстанавливается по незавершённым состояниям PostgreSQL. Redis — транспорт задач, не единственное хранилище расписания, отправок и бюджета.

### 6. Конвейер проверки и управление параллельностью

1. Планировщик выбирает due-поиски и получает lease с token. Один активный проход на поиск; все операции фиксируют его revision.
2. Запросы OLX проходят общий rate limiter. Поиски обслуживаются справедливо; одновременность анализа и медиа не увеличивает разрешённую нагрузку на OLX.
3. Сборщик получает страницы, выделяет объявления, исключает внешние баннеры, сохраняет фактический охват.
4. Для увиденных ID обновляет минимальное присутствие даже при отклонении; повторные свежие детали используют общий кэш.
5. Применяет только те дешёвые фильтры, для которых данных достаточно. Поиск слов в описании нельзя заменить отрицательной проверкой одного заголовка.
6. Получает подробности кандидатов и применяет правила полного текста. Неудачная загрузка даёт `pending_details`, а не reject.
7. Запускает ИИ по режиму и лимитам; после успешной валидации обновляет решение.
8. Сохраняет подходящее объявление и медиа; одной транзакцией создаёт допустимое событие уведомления в outbox.
9. Перед отправкой повторно проверяет текущую revision, активность, hidden, quiet hours и ранее доставленные события. Устаревшее задание не должно отправить результат отменённых правил.
10. Фиксирует полный, частичный или ошибочный проход. UI получает реальные счётчики; неизвестный total не показывай как «100%».

Повторная команда проверки во время существующего прохода возвращает тот же run, а не создаёт дубль. Для технических lease используй ограниченный срок и продление; после потери lease старый worker не имеет права записывать финальное состояние как текущий. Не держи долгую транзакцию БД во время HTTP-вызова.

Пауза останавливает будущие проходы и новые отправки этого поиска, не удаляет архив. Сохраняет очередь допустимых совпадений; после возобновления выполняется восстановительный обход и применяются тихие часы/дайджест. Если карточка одновременно соответствует другому активному поиску, тот может уведомить о ней один раз.

Не прекращай сканирование на первом знакомом ID. Продвижение и подъём старых объявлений меняют порядок. Реализуй перекрытие страниц, ограничение глубины, периодическую глубокую сверку и catch-up после простоя. В UI достаточно строки «Проверены 3 страницы; часть выдачи могла остаться за пределами обхода».

Предустановки: интервал 15 минут; не менее 10 минут в обычном UI; глубина 3 страницы для регулярного прохода; глубокая сверка раз в сутки в пределах общей квоты. Это осторожные начальные настройки продукта, а не официально разрешённые лимиты OLX. Все пределы подчинены настройкам подтверждённого источника. До 10 поисков — ориентир личного пилота, не пожизненный лимит схемы.

### 7. Правила отбора

Статусы решения: `match`, `reject`, `uncertain`. Операционные состояния `pending_details`, `pending_ai`, `ai_error` не смешивай с оценкой товара. В UI ожидающие и сомнительные входят в фильтр «На проверке» с точной причиной.

Обычные правила: диапазон цены; регион и поддерживаемый радиус; состояние; частный/бизнес; исключение продвинутых; нужные/запрещённые слова; тип объявления. Баннеры исключаются всегда. Продвинутый товар остаётся товаром и обрабатывается отдельным флагом; неизвестный признак продвижения не объявляй false.

Нужные слова: группы с логикой «любое внутри группы» и «все группы обязательны»; scope `title`, `description`, `both`; точная фраза или слова. Запреты — отдельные chips с тем же scope. Нормализация Unicode, регистра, пробелов и границ слов. Не используй пользовательский regex как основной механизм; короткая подстрока не должна произвольно матчить другую модель. Синонимы только видимые, без незаметного расширения.

Строгий запрет «ремонт» исключит «не был в ремонте». Смысловое условие «не ремонтировалась» относится к ИИ и должно учитывать отрицание. Эти режимы подпиши по-разному. Требования по неизвестным данным направляют в «На проверке» по умолчанию; пожелания влияют на порядок, но не ослабляют обязательные условия. ИИ не отменяет жёсткий ценовой максимум.

### 8. Первый запуск, версии и уведомления

Первый запуск по умолчанию заполняет ленту, без индивидуальных сообщений о старых товарах. После исходного обхода отправь один итог. На этапе запуска доступны альтернативы «Лучшие 5» и «Все с ограничением темпа» под дополнительными параметрами.

Зафиксируй начало baseline, проверь первые страницы повторно после его завершения. Если дата публикации не доказана, не утверждай, что найденное в ходе baseline объявление появилось после начала: положи его в исходный список. Неизвестные случаи покажи в итоговом отчёте. Время обнаружения и публикации — разные поля.

Изменение правил увеличивает revision, запускает переоценку доступных сохранённых данных и новый обход. Изменение названия не меняет смысл отбора и не требует ИИ. Не отправляй массово старые совпадения после редактирования. Результат теста несохранённого черновика не записывай в историю отправок рабочего поиска.

| Событие | Условие отправки |
|---|---|
| Новый подходящий ID | После baseline, согласно текущим правилам и режиму уведомлений |
| Тот же ID в другом поиске | Добавить связь; первичное сообщение в чат не повторять |
| Теперь подходит после изменения товара | Только при включённом событии; не путать с редактированием требований владельцем |
| Падение цены | Включаемое событие, сопоставимая цена, порог по процентам или сумме |
| Ручная проверка | Обычные правила отправок, без сброса dedup |
| Перезапуск/потеря очереди | Подтверждённые доставки не повторяются |

Для скидки сравнивай цену с последней успешно сообщённой ценой, чтобы несколько небольших снижений могли достигнуть порога; после подтверждённой отправки обнови опорную цену. Если скидки включены позже, зафиксируй текущую цену как начальную точку без ретрорассылки. По умолчанию событие выключено, готовый порог после включения — 5%; альтернатива — конкретная сумма. Если несколько поисков дают одно событие скидки, отправь его один раз владельцу.

Outbox обеспечивает отсутствие обычных дублей, но Telegram может принять сообщение при потерянном сетевом ответе. Тогда `delivery_unknown`, находка остаётся в Mini App, автоматической повторной отправки нет. Явный временный отказ и `429/retry_after` обрабатывай ограниченным повтором. `403` от владельца, блокировавшего бота, отключает доставку и показывает один понятный статус.

Режимы: немедленно и дайджест; тихие часы с интервалом через полночь и часовым поясом; ограничение темпа. После тихих часов очередь сворачивается в дайджест при накоплении, а не взрывается сотней карточек. Не присылай уведомление о каждой краткой сетевой ошибке; одно о длительной остановке, одно о восстановлении.

### 9. OpenRouter: полезный анализ с ограничением расходов

Ключ хранится на сервере. В первой личной версии ввод только через `.env`/setup; в Mini App показывай состояние подключения, список моделей и лимиты, а не редактор ключей. Без ключа скрывай недоступные настройки до включения секции с понятным объяснением; другие функции остаются рабочими.

Поиск хранит `ai_mode=off|ambiguous|all_candidates`, точный model ID, инструкцию, обязательные смысловые критерии/пожелания, дневной лимит и разрешённый fallback. Если критерий можно проверить только ИИ, любой кандидат с непроверенным критерием идёт на ИИ независимо от режима «неоднозначные». ИИ оценивает кандидатов после дешёвых фильтров, а не каждую строку выдачи.

Список моделей/поддерживаемых параметров и тарифы получай сервером, кэшируй с датой обновления. Не фиксируй неподтверждённую «самую дешёвую» модель или устаревшие цены. Предложи один проверенный недорогой text model, доступный текущему ключу и поддерживающий JSON Schema; при невозможности проверить покажи выбор model ID и недоступность проверки. Не расходуй деньги на незаметные сравнительные бенчмарки.

Ответ: `response_format=json_schema`, `strict=true`, `require_parameters=true` для маршрутизации совместимого провайдера; затем серверная Pydantic-валидация. У разных провайдеров ограничения схемы отличаются — совместимость нужно проверить реальным минимальным запросом с разрешённым бюджетом или тестовым ответом, обозначенным как тестовый.

Схема включает: `decision`, `value_label`, `summary`, `matched_requirements`, `violated_requirements`, `unknown_requirements`, `extracted_attributes`, `evidence`. `value_label` — `very_interesting|interesting|ordinary|doubtful|unavailable`; каждое доказательство содержит поле источника и дословный короткий фрагмент. Не показывай «93% исправности», уверенность в честности продавца и рыночную стоимость из памяти модели. Если сопоставимой выборки нет, оценивай соответствие пользовательской задаче, а не скидку относительно выдуманного рынка.

Системная инструкция отделяет текст объявления как недоверенные данные. Модель не имеет tools, секретов, истории Telegram и возможности менять поиск. Отрежь ненужные контакты; проверь цитаты относительно исходного текста. В длинном описании не удаляй середину молча: сообщи о неполноте, не считай неизвестное обязательное условие выполненным.

Ключ кэша: значимые данные товара + текущая цена, если она используется, + canonical rules hash + версия системной инструкции/схемы + model/provider policy. Переиспользование между поисками допустимо только при совпадении всех значимых условий.

Резервируй стоимость в PostgreSQL до вызова с учётом ограничения входа/выхода и текущего тарифа. Одновременно учитывай глобальный дневной/месячный и поисковый лимиты. Списывай фактическую стоимость после ответа; при неизвестном результате вызова резерв не освобождай без доказательств. Нет тарифа — нет безопасного платного вызова. Это внутренний ограничитель расходов, не гарантия абсолютного потолка счёта внешнего провайдера при неизвестных начислениях. Fallback выключен по умолчанию и не превышает остаток лимита.

Предустановки внутренних лимитов: $0.25 в сутки и $5 в месяц глобально; $0.10 в сутки на поиск. Нулевой лимит запрещает вызовы. Анализ тестовой выборки тоже оплачивается и входит в эти лимиты; перед его запуском UI показывает максимальный установленный предел на эту проверку. Без подтверждённой цены не показывай фиктивные $0.00.

При ошибке или лимите сбор работает, обязательный ИИ-кандидат остаётся `pending_ai`, а карточка показывает «Анализ ожидает лимита/подключения». Возобновляй ограниченными пачками, без тысяч одновременных запросов.

### 10. Медиа, актуальность и очистка

Сохраняй до 10 доступных фото только подходящих или вручную сохранённых товаров. Проверь MIME, сигнатуру, размер и декодирование; ограничь pixel count. Оригинальную доступную копию и миниатюру храни в постоянном томе, пути генерируй сам. SVG/HTML и имена файлов из URL не принимай как изображения.

Галерея получает авторизованный URL медиа через API. Токен бота и Telegram download URL не попадают на клиент. Используй `file_id` только как кэш для повторной Telegram-отправки, не как единственную копию.

Основной формат уведомления — одна обложка с короткой подписью и двумя кнопками. Остальные фото в Mini App. Нет обложки — текстовое уведомление с повтором загрузки в фоне; запись не теряется. Альбом оставь дополнительной настройкой, только если реализуешь корректные ограничения Bot API и отдельное сообщение кнопок; не включай его ради видимости полноты.

Хранение по умолчанию: обычные фото 30 дней, полные описания/анализы 90 дней, сохранённые до ручного снятия в пределах лимита диска. Удаление медиа по сроку не удаляет историю отправок доступного объявления; старая карточка показывает «Фото больше не сохранены», а не сломанный элемент.

Проверка прямых ссылок раз в сутки в пределах квот. Первый уверенный сигнал снятия — `availability_pending`; повтор через 6 часов; только второй независимый подтверждённый сигнал запускает полное удаление. Таймаут, CAPTCHA, `403`, `429`, `5xx` и ошибочная структура не являются сигналами снятия. Просто отсутствие в выдаче тоже не считается снятием.

После подтверждённого снятия удалить карточку, версии, текст, анализы, фото, связи, пользовательские saved/note, события и историю уведомления. Удаление имеет приоритет над избранным. Не сохраняй tombstone ID для подавления нового появления. Другой/вернувшийся ID будет обработан как новый. Отправленные сообщения и фотографии в Telegram и старые резервные копии — отдельные копии; удаление из живой базы не выдавай за гарантированное удаление из них. Ограничь хранение резервных копий и опиши это в документации.

Для удаления файлов используй идемпотентное задание с повтором: БД не должна обещать освобождённый диск, пока операция не завершена. При удалении поиска останови его задания; общие товары оставь, если нужны другому поиску или сохранены владельцем.

### 11. Интерфейс: навигация и правила упрощения

Ровно три верхнеуровневых маршрута: `/searches`, `/findings`, `/settings`. Вложенные: `/searches/new`, `/searches/:id`, `/searches/:id/edit`, `/findings/:id`. «Избранное» и «Сомнительные» не являются четвёртым и пятым разделами. Используй query-параметры для фильтра поиска/статуса и глубоких ссылок.

На корневых экранах нижняя навигация, на редакторе и подробностях — контекстный назад. Одно главное действие на экран. Операцию не дублируй одновременно в header, плавающей кнопке и нижней панели. В Telegram используй одну основную нижнюю кнопку через адаптер; внутри обычного браузера тот же action отображай своим footer. Оба варианта одновременно запрещены.

Редкие операции — меню `⋯`; настройки — последовательно раскрываемые группы. Никаких FAB, sidebar на телефоне, длинного dashboard с графиками, большого логотипа и приветственного баннера над полезными карточками. Пустое состояние само объясняет следующий шаг.

### 12. Экраны и действия

| Экран | Состав и расположение действий |
|---|---|
| Поиски | Заголовок + «+» для добавления; карточки: название, краткие условия, статус, последнее обновление, число новых. Единственный быстрый control — активность. Тап карточки открывает подробности |
| Новый поиск / редактор | Одна прокручиваемая форма: ссылка и название, фильтры OLX, свои правила, ИИ, режим проверки/уведомлений. Нижнее действие «Запустить поиск» или «Сохранить изменения». Дополнительный тест — внутри группы правил |
| Подробности поиска | Условия, активность, последний результат и состояние текущей проверки; «Находки этого поиска» ведёт в общую ленту с фильтром. `⋯`: изменить, проверить сейчас, открыть поиск в OLX, копировать, удалить |
| Находки | Selector поиска «Все поиски», фильтр состояния, сортировка; компактные карточки в один столбец на телефоне. В карточке фото, крупная цена, название, город, время обнаружения, одна метка оценки. Тап открывает товар; одна bookmark-иконка сохраняет |
| Подробности находки | Галерея, цена, заголовок, свойства, поиски совпадения, короткое объяснение, риски/неизвестное, раскрываемое описание. Bookmark в header; `⋯` для скрытия и заметки. Единственное основное действие — «Открыть в OLX» |
| Настройки | Четыре компактные группы: уведомления, ИИ и расходы, хранение/экспорт, состояние подключения. Не выводи внутренний мониторинг инфраструктуры таблицей на весь экран |

Фильтры находок: «Подходят», «На проверке», «Сохранённые»; скрытые доступны через дополнительные фильтры. `saved` и `hidden` — пользовательские признаки, `match/uncertain` — решение. Выбор режима должен иметь точную серверную семантику; сохранённое сомнительное видно в сохранённых, а скрытие не отменяет bookmark.

Цена оформляется крупнее заголовка. Пример карточки: «11 500 грн», «Steam Deck 512 GB», «Житомир · обнаружено 12 мин назад», «Интересно». Не выводи ID, URL и все причины прямо в ленту. Нет ИИ — нет фиктивной ИИ-метки. Общая лента показывает товар один раз, даже если совпал с несколькими поисками.

### 13. Визуальный язык и доступность

Спокойный современный инструмент: нейтральный фон, чуть отличающиеся поверхности, один акцент, хорошо читаемая типографика, реальные фото. Используй Telegram theme params как основу, `system-ui`, числовую табуляцию для цен, сетку отступов 4/8/12/16/24/32 px. Основной padding 16 px, радиус карточки 14 px, controls 12 px. Основной текст 15–16 px, вторичный 13 px, заголовок 22–24 px, цена 20–22 px. Акцентный fallback — `#2563EB` в светлой и `#60A5FA` в тёмной теме.

Не используй декоративные градиенты, кислотный неон, стеклянные панели, emoji вместо основных иконок и тяжёлые тени. Работают светлая, тёмная и нестандартные темы Telegram; контраст текста и действий проверяется отдельно. Статус имеет текст, не только цвет. Touch target не меньше 44×44 px, явные labels, keyboard focus, корректные роли диалогов. Уважай `prefers-reduced-motion`.

Начальная ширина контроля 360–430 px, проверка от 320 px. На desktop контейнер до 960 px и две колонки находок, та же навигация. Фиксированные панели учитывают Telegram safe areas, клавиатуру и изменяющийся viewport; не создавай двойной отступ, накладывая два эквивалентных safe-area inset. Внешняя ссылка открывается через Telegram adapter с браузерным fallback.

### 14. Черновики, состояния и обратная связь

Форма сохраняет черновик отдельно от рабочего поиска. Обновление страницы восстанавливает несохранённые поля, но не включает мониторинг. Выход с изменениями: «Продолжить редактирование» / «Выйти без сохранения»; закрытие приложения учитывает наличие черновика. Уже активный поиск продолжает жить по сохранённым правилам.

Валидация возле поля: URL, min≤max, диапазон/валюта, модель при включённом ИИ, бюджет≥0, интервалы и часы. «Сохранить» недоступно без изменений или при неверных данных. Проверка черновика требует валидных условий; paid AI test должен быть явно обозначен. Подстановка названия поиска происходит один раз при импорте, не перезаписывает ручной текст.

Тест условий: до 10 кандидатов, отдельный dry-run, ограниченный сетевой/ИИ-бюджет; ничего не рассылает и не меняет baseline. Результаты «Подходит / Не подходит / Неясно» с одной главной причиной; дополнительные причины раскрываются. Изменение формы помечает результат теста устаревшим.

Обязательные состояния: initial loading/skeleton, пустая лента, пустой фильтр, загрузка следующей страницы, offline, ошибки импорта, частичный сбор, блокировка источника, анализ ожидает, недостаточно бюджета, фото отсутствует/очищено, недоступная удалённая карточка, авторизация истекла, доступ запрещён. Не заменяй ошибку пустым состоянием «ничего не найдено». Stale-данные оставляй видимыми с временем актуальности.

Переключатель активности и bookmark обновляй optimistic с rollback при ошибке. Запуск, удаление и редактирование сохраняй только после server confirmation. Toast — для короткого подтверждения; объяснение длительной проблемы — рядом с проблемным объектом. Никаких модалок «успешно» после каждого сохранения.

### 15. API и авторизация

Сервер валидирует Telegram initData: подпись по официальному алгоритму, `auth_date`, Telegram ID владельца. `initDataUnsafe` — только предварительное оформление, не источник доверия. Обменяй валидный initData на короткую серверную сессию; не передавай raw initData в URL и журналы. Проверяй ownership во всех операциях, включая медиа, экспорты и ссылки конкретного объявления. Защити cookie-сессию от CSRF/неразрешённого Origin, CORS ограничь собственным доменом. Development auth возможен только с явным локальным флагом, не в production.

| Метод/маршрут | Смысл |
|---|---|
| `POST /api/v1/auth/telegram` | Авторизация по raw initData |
| `GET /api/v1/me` | Владелец, settings, capabilities, состояние подключений |
| `POST /api/v1/search-imports` | Разобрать URL и создать черновик; известные/неизвестные поля |
| `GET/PATCH /api/v1/search-drafts/:id` | Получить/сохранить черновик |
| `GET /api/v1/filter-schemas` | Поддерживаемые категории и поля |
| `GET/POST /api/v1/searches` | Список и создание; revision в ответе |
| `GET/PATCH/DELETE /api/v1/searches/:id` | Управление поиском с проверкой ожидаемой revision |
| `POST /api/v1/searches/:id/scans` | Проверить сейчас; вернуть существующий active run при повторе |
| `POST /api/v1/search-previews` | Dry-run правил черновика без уведомлений |
| `GET /api/v1/jobs/:id` | Состояние scan/preview/export без публичного доступа |
| `GET /api/v1/findings` | Фильтры, сортировка, opaque cursor, данные карточек без полного текста |
| `GET /api/v1/findings/:id` | Полная сохранённая карточка, фото и объяснения |
| `PATCH /api/v1/findings/:id/state` | saved/hidden/seen/note |
| `GET /api/v1/media/:id` | Авторизованная выдача изображения |
| `GET/PATCH /api/v1/settings` | Настройки владельца с версией |
| `GET /api/v1/ai/models` и `GET /api/v1/usage` | Модели, тарифы с датой и расходы/резервы |
| `POST /api/v1/exports` | Экспорт с фоновым job |
| `GET /api/v1/exports/:id/download` | Авторизованная временная выгрузка |

Единый ответ ошибки: `code`, безопасное `message`, `field_errors`, `retry_after`, `request_id`. Статусы 401/403/404/409/422/429 различаются. Для конфликтующей revision — 409 и возможность перезагрузить текущие настройки, не silent overwrite. Идемпотентные ключи для запуска/create/preview предотвращают двойные действия при повторном тапе. Пагинация keyset по выбранной сортировке + ID, без дублей при догрузке.

TanStack Query хранит server state; React Hook Form — черновик, отдельный UI state — раскрытые секции и модалки. Не копируй все API-данные в глобальный store. После background updates обновляй активные запросы; polling 3–5 секунд только для открытого текущего run, менее частый для общего состояния, при скрытом WebView приостанавливай клиентские обновления. Закрытие UI не останавливает серверные проверки.

### 16. Telegram-чат

Команды только `/start`, `/app`, `/help`; управление поисками выполняется в Mini App. `/start` показывает короткое объяснение и одну кнопку открытия, не длинную клавиатуру всех функций.

Ссылка в чат: короткий ответ «Распознал поиск: Steam Deck до 12 000 грн» и кнопка «Настроить поиск». Кнопка открывает тот же черновик по непрозрачному токену/ID с серверной проверкой владельца; посторонний пользователь не получает доступ. Совпадающий поиск предлагает открыть существующий или явно создать отдельные правила, не молча клонирует.

Уведомление: обложка; заголовок и цена; город; одна строка причины; ИИ-метка только после реального анализа; максимум одно неизвестное важное свойство; название поиска. Кнопки «Открыть в OLX» и «Подробнее». Полное описание, все фотографии и сохранение доступны в приложении. URL объявления проверен сервером. Все тексты продавца экранируются; лимит подписи Bot API учитывается заранее.

Для deep link выбери и проверь один поддерживаемый способ запуска Mini App. Непрозрачный параметр связывает объявление/черновик с владельцем, но сам по себе не заменяет авторизацию. Если клиент не поддерживает конкретный способ, дай обычный вход в приложение, сохранив доступ через ленту.

### 17. Экспорт, бэкап и наблюдаемость

CSV: заголовок, Decimal-цена, валюта, город, состояние, ссылка, поиски, решение, оценка, first_seen, saved. Защити CSV от формул из недоверенного текста. JSON: настройки и результаты с версией схемы, без секретов. ZIP фото — отдельный выбор при наличии архивных изображений. Временные выгрузки удаляй через 24 часа.

Ежедневный бэкап PostgreSQL; отдельный бэкап важных медиа; ограниченный срок хранения копий. Подготовь скрипт восстановления и один тест восстановления в чистую тестовую базу. Бэкап на том же диске — локальная копия; инструкцию внешнего резервирования предоставь отдельно, не объявляй её выполненной.

Журналы содержат request/run ID, коды ошибок и счётчики, но не ключи, raw initData, телефоны и полный недоверенный текст. Health/readiness различают API, БД, очередь и источник; недоступный OLX не обязан убивать весь API. Метрики: последняя успешная проверка, глубина, очередь, доля частичных проходов, ИИ usage/резерв, место медиа и доставки. В UI показывай только сведения, полезные владельцу.

### 18. Проверки, которые действительно доказывают готовность

| Проверка | Обязательное доказательство |
|---|---|
| URL round trip | Поддерживаемые условия сохраняют смысл; неизвестные не пропадают |
| Полное описание | Слово только в описании не теряется на этапе заголовка |
| Смысл и отрицание | «Не был в ремонте», список альтернативных моделей и accessory-only обработаны согласно режиму |
| Обработка рекламы | Баннер не является товаром; продвинутая карточка дедуплицируется с органической |
| Две выдачи, один товар | Одна карточка, две связи, одно первичное уведомление |
| Baseline и редактирование | Старые совпадения не порождают массовую рассылку; stale revision не отправляется |
| Гонка/перезапуск | Уникальные ограничения, lease и outbox выдерживают повтор задачи |
| Неопределённая доставка | Отсутствует автоматическое повторение уже потенциально принятого сообщения |
| Бюджет | Параллельные вызовы не обходят общий резерв; неизвестная стоимость не превращается в ноль |
| Prompt injection | Текст продавца не меняет требования, цитаты сверяются, секретов в input нет |
| Актуальность | Сетевой сбой не удаляет архив; два подтверждённых снятия удаляют всё, включая saved/history |
| Авторизация и SSRF | Чужие ID, старый initData, локальный URL и опасный redirect отклоняются |
| Quiet hours | Интервал через полночь, timezone и дайджест после паузы работают |
| Полный UI-сценарий | Импорт → редактирование → test → запуск → находка → saved → OLX → пауза |
| Развёртывание | Чистый Compose поднимает сервисы и миграции, данные переживают рестарт |

Используй осмысленные фикстуры: валидная выдача, пустая выдача, рекламный блок, блокировка, сломанная структура, полное описание, несколько валют, удалённая страница, фото без URL. Внешние вызовы в обычных тестах замени контролируемыми ответами. Live smoke test и платные ИИ-проверки — отдельно отмеченные действия, не обязательное условие выполнения unit-тестов.

Фронтенд: сборка и typecheck; мобильные снимки 360/390 px и desktop, светлая/тёмная тема; клавиатура, длинные названия, отсутствие фотографий, ошибка и offline. Проверяй отсутствие горизонтального scroll и наложения fixed controls. Не создавай сотни тестов, проверяющих совпадение CSS-классов.

### 19. Порядок выполнения и итоговый комплект

Сначала проверь существующий репозиторий, если он предоставлен, и сохрани работающие части. Затем создай схему и источник, один вертикальный сценарий от URL до уведомления, остальные поиски и UI, ИИ/фото/экспорт, проверки и Compose. Этапы внутренние: не останавливайся после каждого с вопросом «продолжать?».

Если конкретная библиотека или API изменилась, проверь официальную документацию, закрепи совместимую версию и зафиксируй отклонение. Рутинные технические решения принимай сам. Не запрашивай ключи в переписке; перечисли их в `.env.example` и setup. При ограниченном доступе подготовь весь доступный код и проверку конфигурации, назови блокер с конкретным условием снятия.

Итог репозитория: весь исходный код; миграции; lock-файлы; Compose; `.env.example`; `README` с коротким запуском; `docs/SETUP.md`, `docs/ARCHITECTURE.md`, `docs/OPERATIONS.md`; проверенные фикстуры; тесты; команды бэкапа/восстановления; краткий отчёт о проведённых проверках и непроверенных внешних условиях. Никаких рабочих секретов в примерах.

Задание завершено, когда всё реализуемое собрано и проверено, а владелец для реального включения предоставляет только внешние реквизиты и размещение. Наличие внешнего блокера не даёт права оставить фиктивный успешный сбор или скрытые заглушки. «Построено», «проверено на фикстурах» и «проверено с OLX на сервере» — три разных утверждения.
